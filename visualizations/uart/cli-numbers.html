02 · design

Is uart_puts redundant?

No. uart_puts(s) is a shortcut for print_str(uart_putc, s). C's own library has the same pair.

uart_puts(s) like puts

Send to the usual output. You do not choose where. The CLI calls it everywhere, so each call stays short.

print_str(put, s) like fputs

Send to any output you pass in. The HardFault report needs this: it prints with fault_putc, which polls instead of using the interrupt.
The same code, two outputsprint_dec32 and print_hex32 take the sink as a parameter. The normal path uses uart_putc, the fault path fault_putc.
Pure logicfmt.c has no hardware access, so these functions can be tested on a PC.
The wrapper costs one callIt also hides which output is the normal one. Change that once, in uart_puts.
03 · easy to get wrong

Gotchas

Overflow is checked firstparse_u32 tests v > (0xFFFFFFFF − d) / base before it multiplies. Checking after would be too late, the value has already wrapped.
*out is written only on successOn failure the caller's variable is untouched, so cmd_poke can fail on the second argument safely.
do-while prints 0print_dec32 uses do-while so a value of 0 still gives one digit.
Digits come out backwardsv % 10 gives the last digit first, so the digits go into buf and print in reverse.
tokenize edits the lineIt writes NUL bytes into the buffer. Words are valid only while that buffer is untouched.
Too many wordsThe CLI asks for one more word than it allows, so an extra word is noticed and reported as a usage error.
