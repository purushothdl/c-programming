The receiver counts 16 ticks per bit. Then it votes.

A falling edge wakes the receiver. It checks that the start bit is real, then reads the middle of every bit three times and takes the majority. Add noise and watch what the vote does, and what it cannot fix.

Gotchas

A whole flipped bit is invisibleAll three samples agree, so the vote passes it. Only parity can catch it, and only for an odd number of flips.
A short glitch is voted awayIf one of the three samples is hit, the majority is still right. The receiver sets NF to tell you it happened.
A wide glitch wins the voteHit two of the three samples and the wrong value wins. Try lasting 2 ticks at tick 8 or 9.
Idle glitches are rejectedA start bit must read 0 at ticks 3, 5, 7 and again at 8, 9, 10. A short low pulse fails that test and is ignored, with no flag.
Parity is one extra bitEven parity makes the number of 1s (data + parity) even. It finds an odd number of wrong bits, not which.
The count restarts per frameEvery falling edge zeroes the tick counter, so the receiver never drifts across frames (see the clock error page).
Source: RM0390 §25.4.3 (receiver, start bit detection p. 783, oversampling and majority vote p. 785), USART_SR (SVD: PE bit 0, FE bit 1, NF bit 2). The model counts ticks from the detected falling edge and ignores up to one tick of edge-detection delay.
