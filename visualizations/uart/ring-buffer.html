The interrupt writes. main reads. Two counters keep them apart.

Each received byte triggers the interrupt handler. It drops the byte into a ring of slots. main collects bytes later, at its own pace. This page uses 8 slots so you can see every one. The real program uses 64.

02 · ownership

Why there are two counters

The handler can run in the middle of main, so each side gets one counter that only it changes.

head

  • The next slot to write.
  • Only the interrupt handler changes it.
  • main reads it to see if the ring is empty.

tail

  • The next slot to read.
  • Only main changes it.
  • The handler reads it to see if the ring is full.
One writer, no lockIf both sides wrote one variable, an interrupt between main's read and write would erase an update.
A stale read is safeIf main sees an old head, it thinks fewer bytes wait and picks the rest up next pass.
head − tail is the fill level0 is empty, 8 is full. One position could not tell the two apart. Counters that keep counting can.
03 · the mask

Why head & 7 finds the slot

The counter keeps counting, the ring has 8 slots. The slot is the remainder after dividing by 8: the lowest 3 bits. The higher bits count laps. AND with 7 (0b111) keeps the low 3 bits. Drag the slider.

04 · ring size

Why the size must be a power of two

The mask must be all ones (0b111) to keep a whole group of low bits. And the 32-bit counter wraps from 4294967295 to 0, so the slots must carry on in order. That works only when 2³² is a whole number of laps: 4, 8, 16, 64. The table shows 8 counters across the wrap.
