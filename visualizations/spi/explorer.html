RM0390 chapter 26 · SPI

SPI sends the clock along. So the only question is which edge.

UART needs both sides to guess the same timing. In SPI one wire carries the clock, and each edge says when to put a bit out and when to read it. Pick a mode, run a transfer, then build the register value for it.

    03 · why two edges

    Sample on one edge, change on the other

    Wires and gates add small, unpredictable delays. Splitting the two jobs gives the data a half-clock safety margin. The speed is the same: one bit per clock cycle either way.

    Receivers need the input stable for a short setup time before the sampling edge and a hold time after it. A half-clock gap makes both easy to meet. And there is no clock drift: the slave counts nothing, it only reacts to the master's edges.

    05 · easy to get wrong

    Gotchas

    Both sides must use the same modeThe slave reads on the edge its own CPHA names. A different CPHA reads a bit half a clock early or late.
    CPHA 0: the first bit is earlyThe first edge already reads, so the first bit must be on the wire before it. CS going low is what starts that.
    CS frames the transferHigh means the slave ignores the bus and lets go of MISO (high impedance). One CS line per slave.
    Every read is a writeEight clocks shift eight bits in and eight out. To only read, you send dummy bytes.
    Do not change BR mid-transferRM0390 says the BR bits should not change while communication is ongoing.
    Software CS needs SSM and SSIWith SSM = 1 the NSS pin is ignored and SSI is used instead. A master that drives CS from a GPIO normally sets both (see RM0390, NSS pin management).
