The tick arrives by itself. main just sleeps.

SysTick counts down from 15 999 and wraps every millisecond. The wrap raises exception 15, the handler adds one, and main wakes from __WFI() only when 500 ms have passed. Nothing spins, and nothing polls.

02 · the reload value

How many cycles is a tick?

SysTick counts down by one each processor clock. For a period of N cycles, LOAD = N − 1 (PM0214 p. 248). The register is 24 bits wide, so one tick cannot be longer than 1.049 s.

Reload calculator fCK = 16 MHz

Tick ms
A tick this long needs more than 24 bits. Use a software counter: keep the tick at 1 ms and count in the handler.

03 · easy to get wrong

Gotchas

24 bits is the whole rangeLOAD tops out at 0x00FFFFFF: 16 777 216 cycles, 1.049 s at 16 MHz. Longer periods need your own counter.
TICKINT is what wakes mainWithout it the counter still wraps and sets COUNTFLAG, but no exception is pended. WFI then sleeps forever (tab 2).
Plain >= is not wrap-safeCompare (int32_t)(now − next) >= 0. When the counter wraps, a bare compare waits 49.7 days (tab 3).
g_ms_ticks must be volatileThe handler writes it, main reads it. Without volatile an optimised build may keep the old value in a register.
The vector name is exactstartup.s points 0x3C at SysTick_Handler, with a weak default that loops forever. A misspelt handler links and then hangs on the first tick.
A breakpoint stops timeWhile the core is halted for debugging, the SysTick counter does not decrement (PM0214 p. 246).
