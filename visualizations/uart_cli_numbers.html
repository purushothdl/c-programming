Is uart_puts redundant?

No. uart_puts(s) is only a shortcut for print_str(uart_putc, s), and that is the reason to keep it. C's own library has the same pair.

HereC libraryMeaning
uart_puts(s)puts(s)Send to the usual output. You do not choose where.
print_str(put, s)fputs(s, stream)Send to any output you give it.

The file calls uart_puts 14 times. Without the wrapper each call would read print_str(uart_putc, "..."). The wrapper also hides which output is the normal one. If you later change the normal path, you edit one function. The general print_str stays, because the HardFault report needs it with fault_putc. The cost is one extra call.

The steps show what the code does, one line at a time. The two output functions are the real ones from the file. Here the pages only show the bytes arriving, not the USART timing from the TX page.
