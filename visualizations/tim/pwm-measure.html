TIM5 reads the PWM. Every edge leaves a number behind.

PA5 carries the 1 kHz PWM from TIM2. A jumper feeds it to PA0, where TIM5 sees each edge. The hardware keeps the last period and high time and restarts the count, so measure only reads two registers.

02 · who talks to whom

One period, measured

No interrupt is involved. TIM5 captures and resets in hardware, and main reads the result when you type measure. The first tab is a clean 500 µs pulse. The other two are the ways the reading goes wrong.

03 · the counter · model

Where the captures come from

The count restarts on every rising edge. Each edge leaves the count it had just reached, so the two captures are the period and the high time, counted in 62.5 ns ticks.

06 · the input filter · model

    
Why the filter is off

    
The filter passes a level only after N samples in a row. A short high pulse is dropped. Drag the duty and switch the filter to see the trade.

08 · easy to get wrong
Gotchas

  

    
Resolution
62.5 ns
One TIM5 tick. TIM2 steps are 1 µs, so the meter is 16× finer than the PWM it measures.

    
Range
268 s
The 32-bit counter wraps. Fine for a 1 kHz check, not for a log that runs unattended.

    
CPU cost
0 ISRs
Captures run in hardware. The CPU only works when you type a command; between commands it sleeps in WFI.

  

  

    
Pull the PC13 jumper firstA press of B1 would short the PWM output to GND. From the source comment; UM1724 not checked here.

    
No edges, no numbersDuty 0 or 1000 gives a flat pin. After 1 s (line 118) measure says "stuck" and skips the captures.

    
The counter wraps at 268 sA flat pin left that long makes the check pass again, and measure prints old captures. Derived, not run on the board.

    
Add one tickFigure 186 (RM0390 p. 529) shows CNT 0 to 4 with CCR1 = 4, so a span is captured + 1. Still to confirm: CCR1 = 15999 at 1 kHz on the board.

    
The filter is off on purposeLine 60 clears IC1F. With 1111, high pulses under 16 µs are dropped, which hides every duty under 1.6 %.

    
Two reads are not oneCCR1 and CCR2 are read in two separate lines. An edge between them mixes two periods. At a steady duty this does not show. Derived, not run on the board.

  






  
09 · questions
FAQ

  

    

      Why not use an interrupt for each edge?
      
Each edge already overwrites CCR1 and CCR2 in hardware. An interrupt would only add work without adding data, because the program reads the values once, when you ask.

    

    

      Why is the meter finer than the PWM?
      
TIM5 counts 62.5 ns ticks. TIM2 steps in 1 µs. The printed duty matches the set duty because both are counted in the same 16 MHz ticks, so the rounding cancels.

    

    

      Why keep TIM5 at 16 MHz instead of 1 MHz like TIM2?
      
A 1 MHz count would lose 16× of resolution. The price is the wrap: at 16 MHz, the 32-bit count returns to zero after 268 s.

    

    

      What if the signal changes while measure runs?
      
The two reads are separate instructions, so a new edge can land between them. Periods and high times from different cycles can be mixed. This is derived from the code, not run on the board.
